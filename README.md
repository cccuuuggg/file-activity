# file_activity

用 mtime 记录一个目录里哪些文件"还活着"——拍快照、比差异、挑冷件。单文件，只要 Python 3 标准库。

## 为什么写这个

我有一个工作区，几十万个文件、十几个 GB，改了几个月之后已经说不清哪些还在用、哪些是当时解压完就忘了的。

想按"最后被读过的时间"排序，结果发现读不通：**这个环境里 atime 是死的**。挂载是 `relatime`，移动端为省写入实际把它关掉了——实测读一个文件前后 `atime` 完全不变，它只等于创建时间。`stat`、`ls -lu`、`find -atime` 在这里全都没有意义。

所以只能退一步：**用 mtime + size 做定期快照，靠前后两次快照的差集判断"最近在动的是什么"**。这个工具就是干这个的。

## 用法

```bash
# 存一次基线
python3 file_activity.py snapshot 初始状态

# 干活，过一会儿再存一次
python3 file_activity.py snapshot 改完解析

# 比这两次之间发生了什么
python3 file_activity.py diff

# 六个月没动过的东西（默认 30 天）
python3 file_activity.py cold 180

# 所有快照列表
python3 file_activity.py history
```

命令也认中文：`快照` / `变化` / `冷件` / `历史`。

参数：

| 参数 | 说明 |
|---|---|
| `--root DIR` | 要扫描的目录，默认当前目录 |
| `--db PATH` | 数据库路径，默认 `<root>/.file_activity.sqlite` |
| `--all` | 把 `.git`、`node_modules` 这类默认跳过的目录也算进来 |

## 输出

`diff` 会按顶层目录聚合，先给你一个总量，再列最大的 15 个：

```

新增 128 个   临时(120个/48.2MB)  文档(8个/1.1MB)
修改 6 个     当前生产(6个/320.0KB)
消失 41 个    归档(41个/12.4MB)

-- 新增 最大的 15 个 --
   12.1MB     临时/解包/资源包.bin
   8.4MB      临时/解包/字体.ttf
   ...
```

`cold` 先按目录汇总，再列最大的 25 个：

```
180 天没动过的：3,412 个文件 / 2.1GB

目录                    文件数         大小
归档                      2841      1.8GB
工程分析                   571    320.0MB
```

## 一条注意事项

**冷件 ≠ 该删。** 从 tar/zip 解包出来的老素材会带着几十年前的原始时间戳——你以为是两年前的垃圾，其实是上周才解压的库文件。判断一个文件到底还有没有用，得结合它有没有被别处引用、对应的项目还在不在跑，光看 mtime 不够。

这个工具能回答的是"最近谁在动"，不是"哪个可以删"。

## 实现

就一个 `sqlite3` 库、两张表（`snap` 和 `f`）。快照走 `os.lstat`，20000 行一批批量插入；数据库本身从扫描里排除掉，否则每次快照都会把自己算成"新增"。
